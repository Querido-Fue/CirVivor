## Global contracts

- Gameplay, physics, AI, and gameplay timers use the `1/60` fixed step. Presentation and UI use variable-frame time.
- `GameScene` owns the session `GameSystem`. `module/scene/benchmark/BenchmarkScene` owns one `enemyWaveEnabled: false` child `GameScene` whose single GPU session/grid contains enemies, projectiles, and one hidden static player-collision proxy. The auxiliary CPU world renders the matching blue player and boxes; `scene.projectiles` and the global `ObjectSystem` projectile list stay empty.
- Child-session creation reserves the benchmark player proxy first through the public next-fixed endpoint, and enemy batch requests fail closed if that reservation was not accepted. The benchmark `Spawn 100 Enemies` and `Spawn 10 Projectiles` actions then cross the frame-boundary command queue and reserve batches at `GameScene.getNextGpuLifecycleFixedTick()`. The 10 cyan projectiles start at the center target in an even radial pattern. Profile selection destroys and recreates the child GPU session; callers never duplicate its commit/fixed/presentation/draw/destroy lifecycle. Initial arena walls/boxes are compiled into GPU SDF, but a dynamic `Spawn Box` remains CPU-only and does not change that SDF.
- Binary terrain SDF samples use a signed half-SDF-cell surface bias so authored cell faces, rather than blocked cell centers, define the zero contour. The benchmark opts into `sdfSubdivisions: 8`; its setup-only exact EDT limits the measured small-enemy corner contact error to about `0.026` world units while runtime sample/dispatch counts stay unchanged. Each Jacobi world solve samples `predicted_position + position_delta`, composing same-iteration body separation with terrain without an extra dispatch.
- Production gameplay values come from `project/game/script/data/` via direct named imports.
- The Tower has GPU-authoritative combat HP and may die. Tower death permanently moves that Tower's stat share to Lost Share for the run. Living Tower count reaching zero is not default defeat; Core Integrity reaching zero is.
- `Enemy` is a normal purchasable Entity Word usable as Subject and Payload. Valid harmful or self-destructive sentences execute literally; preview warns but does not censor.
- Player-created enemies are real hostile actors with ordinary bounty, wave cleanup, and Overtime Siege Pressure. Player-created Towers share and dilute the remaining living Tower stat budget.
- World, UI, and effects are resolution independent. See the always-read pitfalls before adding visual values.
- GPU body presentation has three distinct profiles: `strict-interpolation`, `reference-clock-extrapolation`, and `capped-accumulator-extrapolation`. Extrapolation is presentation-only, never mutates authoritative position, and the reference clock is capped to one fixed delta so a long render frame cannot overshoot the next physics state.
- Entering or leaving a pause epoch synchronizes GPU body presentation clocks so resume cannot extrapolate across paused wall time.
- Animation ingress requires the frozen `ANIMATION_CATEGORY` identity (`UI`, `GAME_MECHANIC`, or `EFFECT`) separately from easing `type`. `SystemHandler` injects the hidden `uiAnimationDurationScale` setting (`1.0`, clamped `0.1..4.0`) into `AnimationSystem`; only UI animation delta is divided by this live scale. Gameplay/fixed time, camera `GAME_MECHANIC`, visual `EFFECT`, and tooltip hover seconds are not scaled.
- `tooltipDelaySeconds` is owned by the setting definition as `default=0.30`, `min=0`, `max=2`, `step=0.01`, `precision=2`. Settings state, slider, save coercion, and `UITooltipSystem` must consume that schema/default rather than maintain fallback or rounding literals.
- `DisplaySystem` owns WebGPU adapter/device/canvas generation. Ingame code receives only `webGpuPlatformPort`; it must not import the Display singleton.
- `DisplaySystem` also owns the presentation-scoped `WebGpuFrameComposer` and shared `WebGpuBlurService`. `SystemHandler` opens one composer frame around draw plus the final WebGL flush; contributors encode into that frame but must never acquire the canvas texture, finish/submit the command encoder, or mark presentation themselves. Fixed-step physics and bounded diagnostic/event readbacks remain separate submissions because they are not presentation work.
- Production `EnemySimulationBackend` enables two optional presentation auxiliaries by default. `GpuCrowdDensityRuntime` samples only alive hostile Enemy bodies into a fixed `16×16` grid every eight submitted ticks and uses a three-slot lossy readback ring; its immutable CPU mip snapshot is never gameplay, AI, collision, or spawn authority. `GpuTransientVfxRuntime` consumes bounded GPU death events into a fixed 2,048-record overwrite ring and adds one indirect analytic draw without CPU readback; its indirect-args STORAGE_WRITE pass is separate from the INDIRECT-consuming simulation pass. Both auxiliary compute paths use one presentation-only command buffer submitted strictly after the authoritative fixed command buffer in a separate `queue.submit()` guarded by a validation error scope. Auxiliary failure disables only the auxiliary runtimes and must never trigger GPU-world recovery or invalidate contact/event readback. Direct `GpuCircleBodySimulation` tools remain opt-in for both auxiliaries.
- `WebGpuFrameComposer` lazily acquires the canvas target and command encoder, commits at most once, aborts on device-generation/surface drift, and applies committed/aborted callbacks only after the corresponding outcome. GPU renderers that mirror submitted state on the CPU must defer that transition through these callbacks.
- WebGPU blur implementations are registered behind `WebGpuBlurService`; request sharing uses the exact source identity/revision/checkpoint/bounds/halo/sigma/edge/color/format key. Transient textures are exact-descriptor and device-generation scoped. Algorithms and pools may encode or allocate resources, but presentation ownership remains exclusively with the composer.
- Title WebGPU rollout keeps three explicit blur identities: immutable `kawase-compatibility` for legacy-output regression/final fallback, `kawase-optimized` for the low-cost user-selectable Kawase route, and `gaussian-quality` for the higher-quality route. Never silently report one route under another route's telemetry. Optimized Kawase folds requested sigma at or below `0.1px` to a zero-pass identity; every larger request uses one fixed half→quarter→two-filter→full-resolution reconstruction topology. The first active bucket remains `0.125px`, so quantization, halo preflight, preparation caching, and encode validation stay idempotent. Its fixed pixel-center lattice and convex premultiplied reconstruction are required to prevent the old 3.5/7.5 topology-boundary shimmer.
