# 01. Sentence Grammar and Entity Words

## R3 implementation status (2026-08-16)

R3 Enemy Entity Word is complete. The typed catalog/compiler, five-slot `WordSystem`, Q/E semantic input,
aggregate GPU subject snapshot, and atomic persistent Enemy payload path are connected. The production showcase
binds Q to `The Tower shoots Enemies` and E to `Enemies shoot Enemies`. Each execution freezes its start-set;
new children receive GPU-authored `source generation + 1`, become eligible only for later executions, and never
rejoin the current execution. A zero-subject result and a true 0/N capacity rejection create nothing and consume
no cooldown.

R3 implements only `Shoot + Enemy`. The Tower payload, `Enemies shoot The Tower`, other actor nouns/verbs,
Merge, full modifier grammar, the Shop/editor transaction UI, and save integration remain later milestones.

## 1. Runtime model

Display text is never parsed for gameplay. A sentence is authored from typed word instances and
compiled to structured data.

```text
SubjectSelector
→ Action
→ Payload
→ Modifiers
→ AllegiancePolicy
→ TargetingPolicy
→ ExecutionPolicy
```

Example:

```text
Enemies shoot Fireballs.
```

```yaml
subject:
  selector: entity_word.enemy
  teamFilter: hostile
  snapshot: execution_start

action:
  verb: shoot

payload:
  noun: fireball
  teamPolicy: inherit_subject

targeting:
  policy: nearest_living_tower_then_core

execution:
  atomic: true
  generatedSubjectsJoinCurrentExecution: false
```

## 2. Entity Word roles

`Enemy` and `The Tower` are Entity Words. They can select live entities as Subjects and create actors
as Payloads.

| Word | Subject role | Payload role | Payload allegiance |
| --- | --- | --- | --- |
| The Tower / The Towers | living Player Towers | create Player Tower | fixed Player |
| Enemy / Enemies | live Hostile enemies | create Hostile Enemy | fixed Hostile |
| Fireball(s) | live Fireball objects by team/owner scope | create Fireball | inherit Subject |
| Wall(s) | live Wall objects by team/owner scope | create Wall | inherit Subject |
| Mine(s) | live Mine objects by team/owner scope | create Mine | inherit Subject |

The same word instance may have distinct grammatical slots and UI forms. Stable content IDs, not
localized singular/plural strings, own semantics.

## 3. Subject snapshot

At execution start:

1. Validate the compiled sentence and command budget.
2. Select exact live subjects matching the selector.
3. Freeze their `(entityId, incarnation)` set and deterministic order.
4. Apply subject limit or explicit modifier.
5. Execute only that frozen set.
6. Objects generated by the execution may participate in later executions, never the current one.

This rule allows exponential growth across player inputs while preventing infinite recursion inside a
single fixed execution.

```text
Enemies shoot Enemies.

Input 1: 10 subjects create 10 new enemies → 20 total.
Input 2: 20 subjects create 20 new enemies → 40 total.
```

## 4. Literal valid examples

The following are design-valid sentences. In current R3 production, only `The Tower shoots Enemies` and
`Enemies shoot Enemies` have end-to-end actor-payload execution; the others remain explicit future contracts.

```text
The Tower shoots Enemies.
Enemies shoot The Tower.
Enemies shoot Enemies.
Fireballs emit Enemies.
Enemies throw Fireballs.
The Towers merge.
```

The compiler must not contain strategy labels such as `harmful`, `suicide`, `exploit`, or
`recommended`. The UI may derive consequences from preview data.

## 5. Invalidity reasons

A sentence is invalid only for a defined structural/runtime reason:

- missing required slot;
- incompatible Subject capability and verb;
- payload unsupported by the verb implementation;
- unsupported modifier group combination;
- no atomic transaction path for required mutation;
- exact subject identities are stale;
- world capacity cannot hold the complete atomic result;
- command/generation budget exceeds a hard runtime bound;
- current phase forbids execution, such as Shop or Pause.

`This will probably kill the player` is not an invalidity reason.

## 6. No-subject behavior

When a valid sentence has zero subjects:

- execution produces no result;
- cooldown is not consumed;
- no command is partially staged;
- UI displays the zero-subject reason;
- another sentence whose Subject exists remains usable even with zero Towers.

## 7. Actor payload semantics

Actor payloads are real persistent actors, not projectiles with an actor skin.

### Shoot + Actor

- Spawn at/near the Subject surface.
- Receive initial launch velocity toward the action target.
- Remain persistent; no projectile lifetime.
- Begin actor AI or player-group control from the next fixed tick.
- Use a short source-overlap grace policy if required by collision safety.

### Throw + Actor

- Spawn in an airborne/ballistic state.
- Actor AI/control is suspended while airborne.
- Land at the targeted point, then activate ordinary actor behavior.

### Emit + Actor

- Spawn around or from the Subject with minimal launch movement.
- Activate ordinary behavior immediately or from the next fixed tick.

### Summon + Actor

- Spawn at a validated world point without a travel phase.
- Must use atomic capacity and terrain placement checks.

These are baseline semantics. Every verb must document its actor-payload implementation instead of
silently converting the actor to a different noun.

## 8. Enemy word shop behavior

Current R3 publishes Enemy as an ordinary `shopEligible` Subject+Payload offer with runtime preview metadata.
The five-offer purchase/reroll/duplicate/upgrade UI and its transactions remain R8 work; catalog eligibility is
not a claim that the Shop screen is implemented.

- Enemy is eligible for the normal five-offer word shop.
- It uses ordinary purchase, reroll, duplicate, upgrade, and sentence-slot rules.
- There is no separate mandatory Threat Contract for Enemy.
- Preview must show expected hostile count, bounty potential, Siege Pressure, and Tower dilution when relevant.

## 9. Localization

The compiler stores IDs such as:

```text
word.subject.enemy
word.entity.tower
verb.shoot
noun.fireball
```

English rendering may change between singular and plural:

```text
The Tower shoots an Enemy.
The Towers shoot Enemies.
```

Korean rendering is produced from the same structure. Neither localized output is executable input.
